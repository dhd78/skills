# 新闻日报（约 50 条）

一次一份，按需触发，不自动跑。核心不是「找到新闻」，是**在噪声里标出哪条能信、哪条值得看**。

> 工具名说明：下文 `web_search` / `web_fetch` 指宿主提供的「网络检索 / 网页抓取」工具；换 agent 时替换成对应工具名即可。

## 一句话标准

每条都要能回答「我知道了一件什么事」，而不是「我知道了一个数」；
同一件事只出现一次；文化 / 时尚 / 娱乐占 20%–40%。

## 硬性配额

| 项 | 要求 |
| --- | --- |
| 条数 | 50（±5，宁缺毋滥） |
| 三节 | 世界与政策 10–14；经济与科技 16–22；文化 / 时尚 / 娱乐 10–20 |
| 覆盖 | 国家/地区 ≥ 15；领域 ≥ 15 类 |
| 文化占比 | 20%–40% |
| 主题簇 | 单簇 ≤ 总数 10%（50 条即 ≤ 5 条） |
| 格式 | 每条「标题 + 一句话」，行尾「地区 / 领域 / 来源 / 日期」 |
| 标题 | ≤ 30 字，**不以国名开头**（地区只作元数据） |
| 八卦 | 必标「已证实 / 传闻 / 已辟谣 / 争议」 |

## 七步流程

1. **读底账**：先读已发索引（近 30 天标题，见 `底账/已发索引.md`；首次使用先建空索引），这是去重基线；再读失败模式，避开已知坑。
2. **分桶检索**：按地区桶 + 领域桶各来一轮，每桶 4 个查询。**单批不超过 8 个查询**（12 桶 × 4 查询并发会超时并整批丢结果）。
3. **选稿**：按配额挑，先定「今天发生了什么事」，再按地区/领域补缺口；剔除旅行社广告、行情页、赛程表、纯榜单。
4. **补原文**：对关键条目 `web_fetch` 核对事实与日期，失败一次就回退标题，不重试。
5. **写报**：按 `references/输出模板.md`，开头标截止日 / 条数 / 文化占比。
6. **更底账**：已发索引追加、成本台账记一行、来源清单补域名、日记记口径。
7. **自检**：按 `references/验收自检.md` 跑一遍，再放到 `输出/待审/`。

## 检索接口降级时（重要）

`web_search` 有时只返回**标题 + 链接**，snippet 与 publishedAt 全空。此时：

- 不要编细节：一句话只写标题能支撑的事实；
- 关键条目抓原文（`web_fetch`），正文里拿事实和日期；
- 日期优先级：正文日期 > URL 里的 `/2026-11/09/`、`/20261109/` > 检索元数据；
- 抓不到正文的条目，在交付说明里标「仅依据标题」。

## 日期与去重

- `publishedAt` 有 UTC 偏移，比中文站日期早一天很常见；**以正文或 URL 为准**。
- 旧期出现过的同一个事件，只有「确有新进展」才收（例如从「计票中」到「授权组阁」、「大会前瞻」到「大会开幕」），并在自检表注明。
- 判断重复不要只看标题：抓 2–3 个共现词，或直接对比事件主体 + 动作。

## 抓取与解析

- `web_fetch` 对 `news.cn`、`people.com.cn`、`gov.cn`、`un.org`、`cctv.com` 等多数可拿全文；外文站（部分）会返回空正文。
- HTML 转正文的稳健做法：去 `<script>/<style>` → 标签换行 → 只保留含「。！？」且长度 > 40 的行 → 取前 5 段。纯正则抽 `<p>` 常拿到导航。
- 正文里再抽日期：`datePublished` / `published_time` 优先，其次正文首个 `20xx-xx-xx`。

## 不要做

- 不做「今天最值得看的 5 条」推荐位；
- 不收纯票房 / 纯指数 / 纯榜单（除非能读出结构变化）；
- 不编造、不洗稿、不碰付费墙与隐私；
- 不每天自动跑、不主动打扰。
